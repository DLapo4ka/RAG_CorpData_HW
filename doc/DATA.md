# Данные и назначение репозитория

Документ описывает, какие данные использует RAG-система по кулинарным рецептам, откуда они взяты и что именно попадает в индекс.

## Назначение репозитория

**Для кого:** люди с диетическими ограничениями, ЗОЖ-энтузиасты, занятые профессионалы, которые хотят быстро находить рецепты по ингредиентам и питательной ценности.

**Что демонстрирует:**
- полный offline-pipeline: сырые данные → документы → чанки → TF-IDF индекс → поиск → demo-ответ;
- ответ только по найденным фрагментам с указанием источника (doc_id, score);
- явный отказ, если релевантного контекста нет (< 0.25) или запрос некулинарный;
- Streamlit UI для интерактивной проверки;
- работу с реальным датасетом объёмом 5000+ рецептов.

**Границы MVP:**
- поиск по словам (TF-IDF), не embeddings и не LLM;
- demo-режим без внешних API;
- локальный корпус (5000 рецептов, ~8000 чанков);
- не production-система, а шаблон для повторения на своих данных.

## Что индексируем

| Поле / артефакт | Индексируется? | Где используется |
|----------------|---------------|------------------|
| `text` (название + ингредиенты + инструкции) | Да | TF-IDF матрица, поиск, demo-ответ |
| `title` | Нет (метаданные) | UI, источники — название рецепта |
| `calories` | Нет (метаданные) | UI, источники — калорийность |
| `id` | Нет (метаданные) | UI, источники — идентификатор |

**Pipeline:**
full_format_recipes.json → datasets.json → documents.jsonl → chunks.jsonl → vectorizer.pkl + matrix.npz
- **Чанки:** нарезка по абзацам, max 600 символов, overlap 80 (`app/chunker.py`).
- **Поиск:** cosine similarity по TF-IDF векторам, `top_k=3`, порог `score > 0.25` (`app/retriever.py`).

## Что не индексируем

| Не индексируется | Причина |
|-----------------|---------|
| `data/raw/full_format_recipes.json` | Исходный файл Kaggle — только для подготовки `datasets.json` |
| CSV-файлы из датасета (`epi_r.csv`) | MVP работает с текстом рецептов, не с табличным анализом |
| Kaggle API | Не используется (скачивание вручную через браузер) |
| Секреты, API-ключи | Demo-режим без внешних LLM |
| `data/processed/*.jsonl` | Промежуточные артефакты, генерируются скриптами |
| `data/index/*` | Индекс пересобирается командой `build_index.py` |

## Состав корпуса (5000 рецептов)

Первые 5000 записей из `full_format_recipes.json`. Каждый рецепт содержит:

| Поле | Пример |
|------|--------|
| Название | "Lemon Rosemary Chicken" |
| Ингредиенты | ["4 chicken thighs", "2 lemons", "2 sprigs fresh rosemary", ...] |
| Инструкции | ["Preheat oven to 400°F", "Combine lemon juice...", ...] |
| Калории | 320.5 |

## Как обновить данные

1. Скачать ZIP с Kaggle (кнопка Download) → распаковать → положить `full_format_recipes.json` в `data/raw/`
2. Запустить подготовку данных:
   ```bash
   uv run python scripts/prepare_data.py

3. Пересобрать индекс:
   ```bash
   uv run python scripts/build_index.py

## Известные ограничения данных

- **Язык:** только английский (русскоязычные запросы получают отказ)
- **Калории:** не у всех рецептов указаны (пропускаются, остальные поля индексируются)
- **TF-IDF:** поиск по ключевым словам, синонимы могут не находиться
- **Ложные срабатывания:** некулинарные запросы, содержащие общие слова (например, "cup", "help"), могут давать score > 0.25
